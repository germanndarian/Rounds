# Rounds

Native iPhone app (Swift / SwiftUI) on a Supabase backend: a social drink tracker for nights out with friends.
Crews start a **Night**, log drinks with one tap, share a live feed and disposable-camera photos, and get a story-style
**morning recap**. The product is framed around **memories and nights out, never volume**.

Full context (state, what's next, rules): vault note `~/Documents/Projects/personal-os/projects/Rounds/Rounds.md`. Read it first when reachable.
Same folder: `Rounds roadmap.md`, `Rounds Supabase setup.md`.

## Stack
- Swift 6, SwiftUI, iOS 18+, Xcode 26+. Project generated by **XcodeGen** from `project.yml` (`Rounds.xcodeproj` is not committed).
- Supabase (`supabase-swift`): Auth (Sign in with Apple), Postgres, Storage (photos), Realtime (live feed).
- Planned Apple frameworks: MapKit, VisionKit (barcode), AVFoundation/PhotosUI (camera), ActivityKit, WidgetKit, App Intents, HealthKit, MusicKit.
- Tests use Swift Testing (`import Testing`). Suite `AppStateTests` in `RoundsTests/RoundsTests.swift`.

## Commands
Run from the repo root. `xcbeautify` is not installed, so filter with grep.
```sh

F='error:|warning:|Test Case|\*\* (BUILD|TEST)'
xcodebuild -scheme Rounds -destination 'generic/platform=iOS Simulator' build 2>&1 | grep -E "$F" | tail -40
xcodebuild test -scheme Rounds -destination 'platform=iOS Simulator,name=iPhone 17 Pro' 2>&1 | grep -E "$F" | tail -40
# one test:
xcodebuild test -scheme Rounds -destination 'platform=iOS Simulator,name=iPhone 17 Pro' \
```

Open a screen directly (Debug builds only; read from `UserDefaults` in `Rounds/App/RootView.swift`):
```sh
xcodebuild -scheme Rounds -destination 'platform=iOS Simulator,name=iPhone 17 Pro' -derivedDataPath build build
xcrun simctl boot "iPhone 17 Pro"       # fails harmlessly if already booted
xcrun simctl install booted build/Build/Products/Debug-iphonesimulator/Rounds.app
xcrun simctl launch booted com.dariangermann.rounds -startScreen live   # onb|home|crew|map|profile|live|recap
```

## Conventions
- `AppState` (`@MainActor @Observable`) is injected with `.environment(app)`; views read it with `@Environment(AppState.self)`.
  Currently in-memory with sample data; Phase 1 replaces it with Supabase-backed data.
- Navigation: native `TabView` (Home, Crew, Map, Profile). Live Night and Recap are `fullScreenCover`s driven by
  `app.showingLive` / `app.showingRecap`. Get home safe is pushed inside Live Night's `NavigationStack`.
- Toasts: `app.show(toast:)`, rendered by `.toasts()` (also apply it to each full-screen cover's root).
- Haptics via `.sensoryFeedback`. Timers use `Text(date, style: .timer)` with `.monospacedDigit()`.
- Unfinished integrations are marked `// TODO:` (backend, camera, location, scanner) or `// TODO(design):`.
- UI uses `Theme` tokens only (see the `nocturne-ui` skill).

## Hard rules (product / App Store)
- Apple rejects apps that encourage excessive drinking. **No leaderboards or rankings by drink count**, no "drink more" copy.
  Rank and celebrate bars visited, badges, photos and streaks of nights out. Profile stats never show drink totals.
- The app is 18+ (highest age rating). The onboarding age gate is a hard stop with no retry loop.
- The BAC estimate is opt-in, shown as a range, always carries "Estimate only. Not for driving decisions.", and is **never shared** with the crew.
- Disposable-camera photos stay sealed until **10:00 the next morning**, enforced server-side, not just hidden in the UI.

## Supabase facts
- Every table needs Row Level Security; default: users access rows only for crews they belong to.
- `supabase/migrations/20261016162943_create_crews.sql` is **empty but already applied remotely**. Never edit or delete it; put schema in new migrations.
- Procedure and SQL patterns: `supabase-migration` skill.

## Done means
- `xcodegen generate` run if files were added/removed or `project.yml` changed.
- Build succeeds and all tests are green (add tests for new behavior).
- No secrets, keys or tokens in the diff; no `service_role` key in the app.
- Hard rules above respected; UI uses `Theme` tokens, no ad-hoc colors.
- No unrelated changes (never stage `build/`).
